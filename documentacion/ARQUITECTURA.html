Principios rectores

  1. API REST pura: el frontend solo habla con la API vía JSON. El frontend es reemplazable (facilita migrar a React sin tocar nada más).
  2. Separación en capas: API → Services → Agents → Models. Cada capa solo conoce a la inferior.
  3. Agentes extensibles: se añaden agentes por país/sector registrándolos, sin modificar el runner.
  4. Modelos intercambiables: los agentes nunca llaman a una API de IA directamente; siempre vía la capa de modelos.

4Base de datos (PostgreSQL)

Tablas (beta)

-- Usuarios: se crea ahora aunque el registro llegue en Fase 3
CREATE TABLE users (
    id            SERIAL PRIMARY KEY,
    email         TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,                  -- bcrypt
    plan          TEXT NOT NULL DEFAULT 'free',   -- 'free' | 'premium' (Fase 5)
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Análisis realizados (histórico por usuario)
CREATE TABLE analyses (
    id           SERIAL PRIMARY KEY,
    user_id      INT REFERENCES users(id) ON DELETE CASCADE, -- NULL = anónimo (beta)
    filename     TEXT NOT NULL,
    status       TEXT NOT NULL DEFAULT 'processing', -- processing|done|error
    error        TEXT,
    origin       TEXT,                            -- 'US' | error de origen
    sector       TEXT,                            -- 'defensive_consumer' | error
    report       JSONB,                           -- informe final (formato por definir)
    model_used   TEXT,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Filings: histórico por empresa (Fase 2)
CREATE TABLE filings (
    id           SERIAL PRIMARY KEY,
    ticker       TEXT NOT NULL,
    company_name TEXT NOT NULL,
    form_type    TEXT NOT NULL,                   -- '10-Q' | '10-K'
    period       TEXT,                            -- ej. 'Q2 2025'
    accession_no TEXT UNIQUE,                     -- identificador SEC
    filing_url   TEXT,
    filed_at     DATE,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_filings_ticker ON filings (ticker);
CREATE INDEX idx_analyses_user ON analyses (user_id);
Preparada para el futuro: users.plan → suscripciones (Fase 5); analyses.user_id nullable → la beta funciona sin login y el historial se asocia luego; report JSONB → flexible al formato final; filings se rellena en Fase 2 con la API de SEC/EDGAR.

7Flujo completo de un análisis (Fase 1)

  1. Usuario sube PDF (multipart) a POST /api/upload
  2. Express guarda el archivo en uploads/ con nombre único
  3. pdf.service extrae el texto del PDF
  4. analysis.service crea registro en analyses (status=processing)
  5. Pipeline: OriginAgent → SectorAgent → AnalystAgent (se detiene en el primer error)
  6. Se guarda report + status=done
  7. Respuesta JSON → result.html muestra el informe

  8. Histórico: GET /api/analyses + vista de historial.
  9. Formato del informe: con tus informes de referencia (afecta al prompt del AnalystAgent y al JSONB).

10Mitigación de riesgos

PDF con tablas/escaneado pierde texto

Extraer texto es el paso 1. Si el texto sale vacío o demasiado corto → error claro: "No se pudo extraer texto".

Coste de API de IA

Empezar con modelo barato (DeepSeek) para desarrollo; limitar el texto enviado a los agentes (primeras N páginas si el informe es enorme).

Migrar frontend a React

Garantizado por la API REST pura: el frontend nunca contiene lógica de negocio.

La IA inventa cifras (alucinación)

Prompt del AnalystAgent: análisis estrictamente sobre el texto del PDF; prohibido inventar cifras no presentes.
