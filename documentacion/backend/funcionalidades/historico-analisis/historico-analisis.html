Histórico de análisis por usuario — Backend

Cada análisis completado se guarda asociado al usuario y se puede listar y filtrar por empresa y por fecha (de los resultados o del análisis).

✓ Implementado y probado · 2026-08-14

Qué hace

Al terminar un análisis con éxito (subida manual o botón "Analizar con IA" de un filing), el backend lo guarda en analyses con el usuario que lo hizo (ticker, empresa, fecha de fin de periodo, informe, modelo y URL del PDF). El endpoint GET /api/analyses lista esos análisis con filtros por empresa y por rango de fechas. Sin sesión no se guarda nada.

Guardado automático

  • Tras el pipeline completo (origen → sector → analista → PDF), con userId: status: done, ticker/company del informe, period_end desde reportingPeriod (AAAA-MM-DD), pdf_url.
  • Se actualiza después con origin, sector, report y model_used.
  • Un fallo de BD al guardar no rompe la respuesta del análisis (solo se loguea).
  • Los endpoints devuelven saved: true/false según hubiera usuario.

Base de datos

ALTER TABLE analyses ADD COLUMN IF NOT EXISTS ticker TEXT;
ALTER TABLE analyses ADD COLUMN IF NOT EXISTS company_name TEXT;
ALTER TABLE analyses ADD COLUMN IF NOT EXISTS period_end DATE;
ALTER TABLE analyses ADD COLUMN IF NOT EXISTS pdf_url TEXT;

CREATE INDEX idx_analyses_user_period ON analyses (user_id, period_end);
CREATE INDEX idx_analyses_user_created ON analyses (user_id, created_at);

GET /api/analyses (requiere sesión)

ParámetroFiltra por
tickerEmpresa (ticker o nombre, ILIKE parcial)
periodFrom / periodToFecha de los resultados (period_end)
createdFrom / createdToFecha del análisis (created_at en UTC)

Respuesta: { ok, analyses: [{ id, filename, ticker, companyName, periodEnd, periodTitle, status, createdAt, pdfUrl }] }. Sin coincidencias → 200 con lista vacía; sin sesión → 401.

Decisiones

  • Sin sesión no se guarda: el anónimo ve el resultado pero no genera ruido en BD.
  • Se abre el PDF en otra pestaña (decisión del usuario): la vista de detalle en la web queda para más adelante.
  • Filtro de fecha de resultados con period_end: usa la fecha de fin de periodo del informe, no la de presentación.
  • Fechas en UTC: el cast evita desfases por zona horaria de la BD.

Pruebas

  • Flujo completo con usuario temporal: registro → verificación → login → análisis guardado → listado con filtros por ticker y rangos de fechas.
  • 401 sin sesión, lista vacía sin coincidencias, node --check OK.
