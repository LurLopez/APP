Análisis del informe (10-Q / 10-K) — Backend

Pipeline completo de 3 agentes (origen → sector → analista), generación de PDF y guardado por usuario. Idéntico para subida manual y para filings de la SEC.

✓ Implementado y probado · actualizado 2026-08-14

Qué hace

Recibe un informe financiero (PDF subido o filing de la SEC) y ejecuta el pipeline: el verificador de origen comprueba que sea financiero, de EE. UU. y un 10-Q/10-K; el verificador de sector comprueba que sea de consumo defensivo (rechazo seguro sin evidencia); y el analista principal extrae las cifras y genera el informe estructurado (dos horizontes, bloques Ventas / Cash Flow / Asignación de Capital) con su PDF descargable. Si algo no cumple el alcance, devuelve un error claro con código.

El pipeline

  1. Origen → financiero? EE. UU.? 10-Q/10-K? → { origin: 'US', formType }
  2. Sector → ¿consumo defensivo? → { sector: 'defensive_consumer' }
  3. Analista → fase 1: extracción de cifras (JSON) · fase 2: informe con las reglas de prompts/consumo-defensivo.md
  4. PDF (pdfkit) → pdfUrl → guardado en analyses si hay sesión (saved)

Regla fundamental: la subida manual y el botón "Analizar con IA" de un filing ejecutan exactamente el mismo pipeline (PDF → texto, HTML → htmlToText).

Modelo de IA (configurable en .env)

VariableValor actualEfecto
AI_PROVIDERdeepseekdeepseek · opencode · mock
AI_MAX_TOKENS16000El informe superaba 8000 tokens y el modelo devolvía vacío
AI_REQUEST_TIMEOUT_MS180000Timeout por llamada (nunca queda colgado)
  • DeepSeek directo es el proveedor activo: 22–23 s por análisis, 4/4 JSON válidos (vs OpenCode Go 145–247 s con fallos intermitentes — medida con el mismo informe).
  • chatJson reintenta una vez ante respuesta vacía o JSON inválido; los 3 agentes lo usan.
  • Los agentes solo hablan con la capa modelProvider; cambiar de API es editar .env.
