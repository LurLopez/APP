Verificación del informe (10-Q / 10-K) — Backend

API de subida y verificación: ¿el PDF es un informe financiero 10-Q o 10-K de una empresa de EE. UU.?

✓ Verificación de origen implementada y probada · 2026-08-12 ⏳ Sector y analista pendientes

Qué hace

Recibe el PDF subido por el usuario, extrae su texto y lo pasa por el agente verificador de origen, que decide si es un informe financiero 10-Q o 10-K de una empresa de EE. UU. Si no lo es, devuelve un error claro que se muestra en pantalla.

Endpoint

MétodoRutaQué haceRespuestas
POST/api/uploadSube el PDF (multipart, campo file, ≤ 25 MB) y lo verifica200 · 400 · 422 · 500
# Éxito
{ "ok": true, "origin": "US", "formType": "10-Q" }

# Error (422, AgentError)
{ "error": "Este documento no es un informe financiero (10-Q / 10-K).", "code": "NOT_FINANCIAL" }

Cómo funciona

  1. Multer recibe el archivo en memoria (máx. 25 MB) y se comprueba que sea PDF (mimetype o extensión).
  2. pdf-parse extrae el texto del PDF (pdf.service.js).
  3. originAgent envía el texto (truncado a 80.000 caracteres) a la capa de modelos IA y espera {"isFinancial": bool, "isUsa": bool, "formType": ...}.
  4. Si algo falla se devuelve un AgentError con mensaje en español; si todo pasa, { origin: 'US', formType }.

Modelos IA (capa de abstracción)

El agente nunca llama a la API de un proveedor: habla con modelProvider.chat(messages).

Qué incluye / excluye

Incluye: subida multipart, extracción de texto, verificación financiero + EE. UU. + 10-Q/10-K, capa de modelos (deepseek/mock), errores con código.

Excluye (pendiente): verificación de sector, analista principal, guardado en BD (analyses), guardado del PDF en uploads/, asociación al usuario.

Pruebas

10 casos verificados: 5 del agente con texto (10-Q ✓, 10-K ✓, no financiero ✗, no EE. UU. ✗, sin FORM ✗) y 5 del endpoint con curl (PDF normal 422, PDF 10-Q 200, sin archivo 400, .txt 422, sin key 500).
