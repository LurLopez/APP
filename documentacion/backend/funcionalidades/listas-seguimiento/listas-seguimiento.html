Listas de seguimiento (watchlists) — Backend

Varias listas por usuario (crear, renombrar, eliminar, añadir/quitar acciones) con una lista por defecto "Favoritos" inmutable. Sustituye a los favoritos.

✓ Implementado y probado · 2026-08-15

Qué hace

El backend guarda en PostgreSQL las listas de seguimiento de cada usuario y su contenido. Cada usuario tiene una lista por defecto llamada "Favoritos" (creada de forma perezosa, no se puede renombrar ni eliminar) y puede crear tantas listas adicionales como quiera. Todos los endpoints exigen sesión (requireAuth).

Base de datos

CREATE TABLE watchlists (
    id         SERIAL PRIMARY KEY,
    user_id    INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name       TEXT NOT NULL,
    is_default BOOLEAN NOT NULL DEFAULT false,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (user_id, name)
);

CREATE TABLE watchlist_items (
    id           SERIAL PRIMARY KEY,
    watchlist_id INT NOT NULL REFERENCES watchlists(id) ON DELETE CASCADE,
    ticker       TEXT NOT NULL,
    company_name TEXT NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (watchlist_id, ticker)
);

Migración automática en db/schema.sql: los favoritos antiguos se copian a la lista "Favoritos" de cada usuario y después se elimina la tabla favorites.

Reglas de negocio

  • Lista por defecto "Favoritos": inmutable — no se renombra ni se elimina (400 con mensaje claro).
  • Nombres: 1–40 caracteres; duplicado por usuario → 409 "Ya existe una lista con ese nombre."
  • Items: ticker válido (^[A-Z0-9.-]{1,10}$); añadir repetido es un upsert (actualiza el nombre de empresa).
  • Cotizaciones: solo en el detalle; si una falla se devuelve null sin romper la lista.
  • Sin sesión → 401 en todos los endpoints.

Decisiones

  • Multi-lista en vez de favoritos: el usuario pedía organizar por listas; la migración conserva los favoritos antiguos.
  • Lista por defecto inmutable y perezosa: sin migraciones al registrarse y UX estable.
  • Upsert de items: añadir un ticker ya presente actualiza el nombre, nunca falla ni duplica.
  • Cotizaciones solo en el detalle: el listado es barato; la tabla con cotizaciones se pide al mostrarla.

Pruebas

  • Migración: 1 favorita antigua conservada; favorites eliminada.
  • Flujo completo con usuario temporal: crear lista, duplicado 409, nombre inválido 400, añadir/upsert/quitar, renombrar, borrar lista, borrar por defecto 400, 404, ticker inválido 400, 401 sin sesión.
  • node --check OK y recursos estáticos 200.
