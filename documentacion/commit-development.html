Commit Seguro e Interactivo para Rama Development

Guía de funcionamiento del programa commit-development.sh, arquitectura de bloqueo contra producción y verificación estricta de token secreto.

✓ Implementado y Operativo · 2026-09-14

Resumen Ejecutivo

El sistema proporciona un mecanismo integral para confirmar y subir cambios al repositorio garantizando el aislamiento absoluto de la rama de producción. Resuelve los riesgos de commits desatendidos por inteligencias artificiales y fallos humanos al subir código experimental.

🛡️ Blindaje de Producción

Bloquea e intercepta automáticamente cualquier intento de commit si la rama activa es production, main o master, conmutando de inmediato a development.

👁️ Auditoría Visual

Clasifica y colorea los archivos afectados antes de pedir el mensaje, mostrando el número total de archivos y su estado exacto.

🔑 Token Secreto Anti-IA

El hook pre-commit exige terminal interactiva humana (/dev/tty). Los agentes y procesos no interactivos tienen bloqueado el commit por diseño.

🚀 Push Exclusivo

Sube única y exclusivamente a origin/development. Si el commit no se realiza o el token falla, nunca se ejecuta el comando de push.

Flujo de Ejecución Paso a Paso

1

Verificación y Redirección de Rama

Comprueba la rama activa con git branch --show-current. Si te encuentras en production, main o master, emite una advertencia de seguridad y ejecuta git switch development automáticamente. Si la rama no es development, te sitúa en ella.

2

Listado Visual Categorizado

Consulta git status --porcelain=v1. Si no hay cambios, finaliza amigablemente. Si hay cambios, los desglosa con código de colores según su estado:

CategoríaCódigo GitSignificado
[NUEVO]??Archivo no rastreado previamente (untracked).
[MODIFICADO]M / M / MMArchivo existente con modificaciones de contenido.
[AÑADIDO]A / AArchivo preparado para seguimiento en el índice.
[ELIMINADO]D / DArchivo borrado del árbol de trabajo.
3

Solicitud Interactiva del Mensaje de Commit

Lee desde /dev/tty garantizando compatibilidad con terminales interactivas. No admite mensajes vacíos ni formados exclusivamente por espacios en blanco.

4

Validación del Hook Pre-commit y Token

Comprueba que el hash del token esté inicializado en ~/.config/cifra-commit-lock/token.sha256. Si falta, lanza el setup. Al ejecutar git commit, el hook solicita el token con caracteres ocultos y verifica el hash con sal (máximo 3 intentos con 300 s de timeout).

Bloqueo de Agentes: Si un agente de IA intenta commitear de fondo, la llamada falla inmediatamente porque no existe una terminal TTY humana disponible.
5

Subida Exclusiva a origin/development

Verifica por tercera vez que la rama activa sea estrictamente development y ejecuta git push --set-upstream origin development. Soporta tanto SSH nativo como HTTPS interactivo mediante GIT_ASKPASS efímero.

Cómo Utilizarlo

Puedes ejecutar el flujo en cualquier momento desde la terminal mediante el script raíz o el script configurado en package.json:

# Opción 1: Mediante script npm (recomendado)
npm run commit

# Opción 2: Alias de desarrollo
npm run commit:dev

# Opción 3: Ejecución directa del script en la raíz
./commit-development.sh

Configuración Inicial del Token de Seguridad

Si aún no has configurado tu token personal, puedes inicializarlo manualmente en cualquier momento ejecutando:

./scripts/commit-token-setup.sh

Este instalador te pedirá que introduzcas y repitas tu token secreto (mínimo 8 caracteres, recomendado 16+), generará una sal aleatoria criptográfica y asegurará el hook con permisos restrictivos.
