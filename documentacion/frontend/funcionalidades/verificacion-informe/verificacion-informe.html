Verificación del informe (10-Q / 10-K) — Frontend

Subida del PDF y verificación real contra la API: estados de los agentes, errores en pantalla y botones de acción.

✓ Implementado y conectado a la API real · 2026-08-12

Qué hace

El usuario sube un PDF (arrastrando o seleccionándolo), pulsa "Analizar informe" y el documento se envía a POST /api/upload. En pantalla se ve el agente Verificador de origen procesando; al terminar: ✓ Completado con el tipo detectado (10-Q / 10-K) o ✕ Error con el mensaje del servidor.

Flujo

  1. Seleccionar PDF → validación cliente (tipo y ≤ 25 MB) → preview con nombre, tamaño y botón de quitar.
  2. "Analizar informe" → panel de análisis visible, agente origin en Procesando, contador en marcha.
  3. fetch POST /api/upload con el PDF.
  4. Éxito → "Documento verificado: 10-Q" + toast + botón "Analizar otro informe".
  5. Error → caja roja con el mensaje exacto del servidor + botón "Reintentar" (conserva el archivo).

Qué incluye / excluye

Incluye: dropzone con arrastrar y soltar, validación cliente, preview del archivo, llamada real a la API, estados por agente (espera/procesando/completado/error), errores del servidor en pantalla, reintentar, analizar otro informe.

Excluye (pendiente): ejecución visual de los agentes de sector y analista, informe final, histórico real del usuario.
