Análisis del informe (10-Q / 10-K) — Frontend

Subida de PDF, pipeline de 3 agentes en vivo con cronómetro, informe estructurado con descarga de PDF y análisis desde la página de empresa.

✓ Implementado y probado · actualizado 2026-08-14

Qué hace

El usuario sube un PDF (arrastrar y soltar o clic, validado PDF ≤ 25 MB) y ve el pipeline de 3 agentes (Origen → Sector → Análisis) ejecutarse en tiempo real con estados, barra de progreso y cronómetro. Al terminar se muestra el informe estructurado (dos horizontes; bloques Ventas, Cash Flow y Asignación de Capital) con el botón de descargar el PDF. Si el informe no cumple el alcance, aparece una caja roja con el error claro y botón Reintentar.

Cómo funciona

  1. Subir PDF → POST /api/upload.
  2. Agentes en vivo: estados (En espera / Procesando / Completado / Error), cronómetro mm:ss y avisos a los 45 s y 240 s.
  3. Éxito → informe (3 bloques) + "Descargar PDF del análisis" (nombre <ticker>-analisis-cifra.pdf).
  4. Error → caja roja con el mensaje del servidor (p. ej. "Este informe no es de una empresa de EE. UU.") + Reintentar.
  5. Con sesión → toast "Análisis guardado en tu histórico" y recarga de "Mis análisis".

Analizar desde la página de empresa

  • Cada filing de la pestaña de informes tiene el botón "Analizar con IA".
  • Navega a /?analizar=TICKER&accession=...; Inicio consume los parámetros, limpia la URL y ejecuta POST /api/screener/company/:ticker/filings/:accession/analyze con la misma UI.
  • "Reintentar" re-ejecuta el mismo filing (pendingFiling).

Pruebas

  • Pipeline completo con KHC 10-Q real: 200 ~21 s, informe con 2 horizontes y 3 bloques, PDF descargable.
  • Botón "Analizar con IA" (TAP): 200 en 22,8 s con DeepSeek; guardado con sesión.
  • Cronómetro mm:ss y avisos progresivos verificados.
Nota de desarrollo: con npm run dev (--watch), guardar cualquier archivo durante un análisis corta la petición en curso.
