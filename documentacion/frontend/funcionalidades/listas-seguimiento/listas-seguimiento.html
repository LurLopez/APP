Listas de seguimiento (watchlists) — Frontend

Popover con checkmarks (ojo de seguimiento) y sección completa de listas con cotizaciones, en un módulo compartido entre Inicio y Empresa.

✓ Implementado y probado · 2026-08-15

Qué hace

El usuario pulsa el ojo de seguimiento de una empresa (en la cabecera de Empresa o en las tarjetas de Inicio) y se abre un popover con todas sus listas: marca la lista (✓) para añadir o quitar la acción, crea listas nuevas al momento o las borra con confirmación de dos pasos. La sección de listas (Inicio y lateral de Empresa) muestra chips por lista y una tabla estilo Investing con las cotizaciones de la lista seleccionada.

El popover del ojo

  • Fila por lista: checkmark ✓ si la acción está en esa lista, nombre, recuento ("3 acciones") y botón de borrar (dos pasos: "¿Eliminar?" durante 3 s; nunca en "Favoritos").
  • Creación inline: input + botón "Crear" (habilitado solo con texto).
  • Accesible: filas con role="button", Enter/Espacio, Escape para cerrar.
  • Cierre robusto: clic fuera, Escape y scroll de página cierran; el scroll interno de la lista NO cierra; al re-renderizar se conserva la posición de scroll.
  • Anclado al ojo, con volteo arriba/abajo y límites de ventana.
  • Sin sesión → toast "Inicia sesión para guardar acciones en listas de seguimiento." + modal de login.

La sección de listas

  • Chips por lista (nombre + recuento), activo con borde naranja; borrable con confirmación de dos pasos salvo la por defecto.
  • Formulario de creación de listas inline.
  • Tabla estilo Investing con la lista seleccionada: Nombre (🇺🇸 + enlace), Símbolo, Último, Apertura, Máximo, Mínimo, Var., % var., Vol., Fecha/Hora con punto de estado de mercado y ojo para quitar.
  • La petición de detalle se repite al cambiar de lista o tras cualquier cambio (siempre cotizaciones frescas).
  • Estados: sin sesión → CTA de login; sin listas → crear la primera; lista vacía → invita a usar el ojo.

Cómo funciona

  1. Watchlists.setAuthenticated(true) al iniciar sesión → refresh() → GET /api/watchlists → estado (listas, pertenencias) + evento watchlists:change.
  2. Clic en el ojo → Watchlists.open(anchor, ticker, companyName) → popover con las listas y sus marcas.
  3. Clic en una fila → toggle(listId, ticker, companyName) → optimista + POST/DELETE a la API + toast + refresh.
  4. La sección (mountSection) se re-renderiza con cada watchlists:change y al cambiar de chip.

Bugs corregidos en esta iteración

  • El desplegable se cerraba al hacer scroll con muchas listas (el listener con captura cerraba con cualquier scroll; ahora solo si el scroll es fuera del popover).
  • El desplegable saltaba arriba al añadir (el re-render perdía el scrollTop; ahora se guarda y restaura).

Pruebas

  • Dos listas de usuario de prueba (Favoritos + "ETT") renderizadas en chips y tabla.
  • Marcar/desmarcar con scroll preservado; cierre con scroll de página; sin cierre con scroll interno.
  • node --check OK y recursos estáticos 200.
